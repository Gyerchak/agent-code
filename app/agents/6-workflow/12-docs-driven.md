---
title: Docs driven
summary: Documentation is part of the deliverable, not a chore
---

Documentation is part of the deliverable, not a chore:

- User-facing: explain what it does and why it matters, then how.
- Code-facing: README with quick start, setup, and common problems.
- Keep docs next to the code so they update together (docs as code).
- A command/API without an example is unfinished.
- Changelog every user-visible change; credit contributors properly.
