---
title: Speed run
summary: Move fast without breaking things
---

Move fast without breaking things:

- Prototype first, perfect later — a working demo beats a perfect plan.
- Use the fastest reliable path: stdlib, native, simplest viable tool.
- Parallelize independent work; don't re-derive what you already know.
- Defer decisions that don't change the architecture (YAGNI).
- Keep the loop tight: change → run → observe. No long unobserved scripts.
- Speed is a feature too, but never at the cost of data loss or secrets.
